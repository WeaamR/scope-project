# مقترح مشروع SCOPE — Client Proposal

## الملخص التنفيذي

SCOPE هو مساعد ذكي يساعد المستقل على فهم طلب العميل قبل الالتزام، وتحديد
المعلومات التي تحتاج إلى توضيح، وتنظيم نطاق العمل، ثم مراجعة الطلبات
الجديدة مقارنة بآخر اتفاق معتمد. يركز الإصدار الحالي مبدئيًا على
المستقلين المبتدئين، وخصوصًا مصممي الجرافيك.

يجمع الحل بين واجهة لإدارة الخدمات والمشاريع، وقاعدة بيانات ومصادقة عبر
Supabase، وتدفقات أتمتة عبر n8n، وقدرات تحليل لغوي باستخدام Gemini. وتظل
مراجعة النتائج واعتماد الاتفاق والقرارات المتعلقة بالتغييرات مسؤولية
المستقل.

## المشكلة والحاجة

يستقبل المستقل أحيانًا طلبًا عامًا لا يحدد بدقة المخرجات أو المقاسات أو
المدة أو جولات التعديل أو مسؤوليات العميل. وقد تظهر التفاصيل أثناء
التنفيذ، أو يطلب العميل إضافات لم تكن واضحة في الاتفاق الأولي. يؤدي ذلك
إلى احتمالية توسع نطاق العمل دون اتفاق واضح على الوقت أو التكلفة.

التحديات تشمل صعوبة تحويل الرسالة إلى متطلبات واضحة، ونسيان الأسئلة
المهمة، والخلط بين الخدمات المتاحة وما طلبه العميل فعليًا، وصعوبة التمييز
بين التعديل المشمول والطلب الإضافي، وتشتت الاتفاقات عبر المحادثات.

## المستخدمون المستهدفون

الفئة المستهدفة في الإصدار الحالي هي المستقلون المبتدئون، مع تركيز خاص
على مصممي الجرافيك. ويمكن توسيع المنصة مستقبلًا لتشمل مستقلين في مجالات
أخرى بعد التحقق من احتياجات كل مجال.

## الحل المقترح والوظائف الأساسية

يوفر SCOPE مساحة موحدة لإدارة الخدمات والمشاريع، وتحليل طلب العميل،
وإظهار ما هو مؤكد وما يحتاج إلى توضيح، ثم إعداد مسودة نطاق عمل يراجعها
المستقل ويعتمدها. وعند وصول طلب جديد، تتم مقارنته بالنسخة المعتمدة.

تشمل الوظائف: إدارة الخدمات والمشاريع، تحليل رسالة العميل، استخراج
الحقائق والنواقص والغموض والمخاطر، اقتراح الأسئلة والرسائل المهنية،
إنشاء مسودة نطاق العمل، اعتماد الإصدارات، اكتشاف التغييرات، وتصنيفها إلى
`within_scope` أو `additional_work` أو `needs_clarification`، وحفظ سجل
المشروع.

## رحلة الاستخدام

1.  تعريف الخدمة وشروطها.
2.  إنشاء المشروع وربطه بالعميل والخدمة.
3.  إدخال رسالة العميل وإرسالها للتحليل.
4.  مراجعة نتائج التحليل والأسئلة المقترحة.
5.  توضيح التفاصيل مع العميل.
6.  إعداد مسودة نطاق العمل ومراجعتها.
7.  اعتماد النسخة المتفق عليها.
8.  مقارنة أي طلب جديد بآخر نسخة معتمدة واتخاذ القرار.

## المكونات التقنية

- Lovable مع React وTypeScript للواجهة.
- Supabase Auth وPostgreSQL وRLS للمصادقة والبيانات والصلاحيات.
- Supabase Edge Functions وRPC للعمليات الخلفية.
- n8n Cloud لتنسيق تدفقات العمل.
- Gemini 3.5 Flash Lite لتحليل اللغة الطبيعية وإرجاع JSON منظم.

## القيمة المتوقعة

رفع وضوح المتطلبات، مساعدة المستقل على طرح الأسئلة المناسبة، تقليل
احتمالية تنفيذ أعمال إضافية دون مراجعة الاتفاق، توفير مرجع للإصدارات،
وتسهيل مراجعة سجل المشروع. هذه فوائد متوقعة نوعيًا وليست نتائج كمية
مقاسة.

## الحدود والاعتبارات

مخرجات الذكاء الاصطناعي اقتراحات تتطلب مراجعة بشرية. لم يُستكمل اختبار
رحلة Scope Resolution كاملة من واجهة المستخدم وفق سجل الاختبارات المتاح.
كما تحتاج ملفات n8n المصدّرة إلى مطابقة مع النسخ الحية قبل اعتبارها جاهزة
للاستيراد. تُرسل بيانات الطلب والمشروع اللازمة للتحليل إلى Gemini عبر
n8n، ويوصى بإضافة تنبيه خصوصية صريح للمستخدم.
